## General Rules

* Do not modify unrelated files.
* Preserve the existing project architecture.
* Reuse existing components, utilities, styles, and design tokens whenever possible.
* Do not introduce unnecessary dependencies.
* Keep the code clean, scalable, readable, and maintainable.

## Responsive Design

The portfolio must provide a consistent experience across:

* Mobile phones
* Tablets
* Laptops
* Desktop monitors
* Large/wide screens

Ensure:

* No horizontal scrolling.
* No overlapping or clipped content.
* Typography scales appropriately.
* Images and media resize correctly.
* Cards adapt to available screen width.
* Navigation works correctly on smaller screens.
* Buttons and interactive elements remain touch-friendly.
* Layouts use responsive design rather than unnecessary fixed positioning.

Test important UI changes across multiple viewport sizes.

## Accessibility

Maintain good accessibility practices.

* Use semantic HTML.
* Maintain a logical heading hierarchy.
* Provide keyboard navigation.
* Provide visible focus states.
* Use accessible buttons and links.

* Ensure interactive elements are usable with keyboard and touch.

## Before Coding

Before making any change:

1. Identify which part of the portfolio the task affects.
2. Inspect the relevant files.
3. Understand the existing implementation.
4. Identify reusable components and utilities.
5. Check the existing design system.
6. Determine the smallest appropriate change.
7. Confirm that the change will not affect unrelated functionality.

Do not rewrite or restructure the project unnecessarily.

---

## After Coding

After making changes:

1. Check for build errors.
2. Check for runtime errors.
3. Test the affected functionality.
4. Verify responsive behavior.
5. Check the browser console for relevant errors.
6. Verify that existing navigation and functionality still work.
7. Confirm that unrelated files and features were not unnecessarily modified.
8. Fix any issues introduced by the change.
9. Briefly summarize what was changed.

---

## Change Management

When fixing a specific issue:

* Focus only on the reported issue.
* Do not redesign unrelated sections.
* Do not change established components unnecessarily.
* Preserve existing behavior unless the task explicitly requires changing it.
* Prefer incremental improvements over large rewrites.

When implementing a new feature:

* Follow the existing architecture.
* Reuse existing components.
* Add new components only when necessary.
* Keep the implementation modular and reusable.

---

## Development Approach

Build and improve the portfolio incrementally.

For larger features:

1. Understand
2. Plan
3. Implement
4. Test
5. Review
6. Refine
7. Verify responsiveness
8. Complete

Do not automatically implement additional features that were not requested.
